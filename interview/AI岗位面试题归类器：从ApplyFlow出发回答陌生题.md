# AI 岗位面试题归类器：从 ApplyFlow 出发回答陌生题

最后更新：2026-05-19

## 0. 核心判断

AI 岗位面试题是背不完的。继续无限补题库，会让你越来越焦虑，也会让回答变成“背材料”。你现在更适合的策略不是装成 AI 研究员，而是把自己定位成：

> 能用 AI 工具和工程流程，把一个真实业务问题做成可演示、可迭代、可评估产品的人。

你的面试优势不在于比算法专业的人更懂模型细节，而在于你有一个可以反复展开的项目：ApplyFlow。只要题目不是纯算法推导，都可以尽量回到这条主线：

> 真实场景 → AI 适合做什么 → 系统边界怎么定 → 怎么评估效果 → 怎么根据反馈迭代

## 1. 不要背题，要背“问题路由”

面试官问的问题再多，底层基本会落到 7 类。

| 题型 | 面试官实际想看 | 你要接回哪里 |
| --- | --- | --- |
| 业务场景题 | 你是不是懂真实用户问题 | ApplyFlow 的求职执行闭环 |
| Agent 架构题 | 你是不是懂 Agent 不等于聊天机器人 | ApplyFlow 的 workflow、状态机、工具边界 |
| 系统边界题 | 你是不是知道 AI 会犯错 | ApplyFlow 的权限、Schema、人工确认；网易内容安全 |
| 评估指标题 | 你是不是能证明效果 | Task / Transcript / Outcome / Grader、投递漏斗 |
| 数据迭代题 | 你是不是会用反馈优化 | Evidence Log、Bad Case、改版前后同口径复测 |
| 工程落地题 | 你是不是能把黑盒变稳定 | AGENTS.md、Focused Review、验证脚本、生产 smoke |
| 知识盲区题 | 你不会时怎么回答 | 先承认边界，再讲理解、项目映射和下一步 |

你不需要把所有题背成标准答案。你只要听出它属于哪一类，再用对应的项目锚点回答。

现有所有面试材料已经按这 7 类重新归档，复习时先看：

- `interview/AI面试资料总索引：按7类题型整理.md`

## 2. 你的三个核心锚点

### 锚点一：ApplyFlow

它负责回答：

- 你做过什么 AI 产品。
- 你怎么理解 Agent。
- 你怎么做系统边界。
- 你怎么做评估。
- 你怎么根据用户反馈迭代。
- 你怎么证明不是玩具 Demo。

一句话：

> ApplyFlow 是我最熟悉的主场。我会把陌生问题尽量转成“这个问题在求职执行 Agent 里怎么出现、怎么解决、怎么评估”。

### 锚点二：网易 AIGC 内容安全策略实习

它负责回答：

- AIGC 和人工内容有什么区别。
- AI 输出不稳定怎么处理。
- Bad Case 怎么记录。
- 内容安全、审核、人工复核怎么做。
- 为什么 AI 产品需要治理边界。

一句话：

> 网易实习是我理解 AI 风险治理的入口，它能帮我回答内容安全、Prompt 边界、人工复核和 Bad Case 复盘类问题。

### 锚点三：Codex 开发流程

它负责回答：

- 你怎么用 AI Coding。
- 你遇到过什么工程难点。
- 你怎么防止模型误改。
- 你怎么做验证、回归和安全门禁。
- 你怎么把概率黑盒放进稳定流程。

一句话：

> 我的开发过程本身也是一个 Agent 治理案例：AGENTS.md 定规则，CONTEXT.md 保现场，验证脚本和 Focused Review 做门禁。

## 3. 万能回答公式

遇到陌生题时，不要急着背定义。按 4 步回答：

```text
1. 先分类：这个问题属于场景 / 架构 / 边界 / 评估 / 迭代 / 工程 / 知识盲区哪一类？
2. 先承认边界：这个点我没有做成完整商业系统，但我在 ApplyFlow / 网易实习里遇到过相似问题。
3. 接回项目：在我的项目里，对应的是哪条链路、哪个问题、哪个取舍。
4. 给方法：如果进一步产品化，我会看什么指标、加什么边界、怎么验证。
```

最常用的口播模板：

> 这个问题我会先拆成模型能力和系统工程两层。模型能不能生成只是第一步，真正决定能不能上线的是场景定义、边界、评估和反馈闭环。在 ApplyFlow 里，对应的是……如果扩展到你说的场景，我会优先看……指标，并用……方式做验证。

## 4. 七类题怎么接回项目

### 4.1 业务场景题

常见问法：

- 你为什么做这个项目？
- 你解决了什么真实问题？
- AI 产品怎么找场景？
- 如果让你做一个 AI 招聘助手 / AI 客服 / AI 研报助手，你怎么设计？

回答方向：

> 先讲真实任务，不先讲模型。一个 AI 产品能不能成立，先看用户有没有连续任务、信息是否半结构化、是否需要判断和解释、是否能形成反馈闭环。

接回 ApplyFlow：

- 连续任务：岗位浏览 → 投递清单 → 状态回填 → 反馈复盘。
- 半结构化信息：JD、城市、行业、用户偏好。
- 判断和解释：为什么推荐、风险在哪里、下一步做什么。
- 反馈闭环：好岗位、不匹配、误判、状态回填。

一句话：

> 我会先判断这个场景是不是值得用 AI。ApplyFlow 里值得用 AI 的点不是点击投递，而是岗位和用户偏好之间存在大量语义判断。

### 4.2 Agent 架构题

常见问法：

- Agent 和 workflow 有什么区别？
- 为什么不用普通规则？
- ReAct、Plan-and-Execute 适合什么场景？
- 多 Agent 和单 Agent + 多工具怎么选？
- Memory 怎么设计？

回答方向：

> Agent 不是“会聊天”，而是围绕目标持续推进任务；workflow 是预定义路径，Agent 更强调动态判断。真实产品里通常两者结合：确定流程用 workflow，不确定判断用模型。

接回 ApplyFlow：

- workflow：岗位导入、排序、投递清单、状态回填。
- Agent 能力：理解 JD、生成解释、识别风险、给下一步建议。
- memory：用户偏好、岗位状态、反馈记录分开存，不把所有历史塞进 Prompt。
- 多 Agent：当前没必要做复杂多 Agent，先用单 Agent + 清晰工具边界更稳。

一句话：

> ApplyFlow 不是让模型自由行动，而是把 Agent 放进 workflow 里。模型做语义判断，系统决定状态能不能推进。

### 4.3 系统边界题

常见问法：

- AI 生成错了怎么办？
- Prompt 注入怎么办？
- 工具调用参数乱传怎么办？
- 用户数据怎么隔离？
- 为什么不做全自动投递？
- 怎么处理隐私和安全？

回答方向：

> Prompt 是软约束，系统边界才是硬约束。越接近用户数据、执行动作和外部提交，越不能只靠模型自觉。

接回 ApplyFlow：

- Structured Output / schema：模型输出必须结构化。
- 权限归属：写路径以 authenticated user 为准。
- 执行门禁：外部投递不自动提交，用户最终确认。
- 数据隔离：demo、真实池、白名单用户分开。
- 网易实习：内容安全里也是 AI 生成 + 人工复核 + Bad Case 复测。

一句话：

> 我不会把高风险动作交给模型直接执行。ApplyFlow 里 AI 可以建议岗位，但加入投递清单、状态回填和真实投递都要有系统边界和用户确认。

### 4.4 评估指标题

常见问法：

- 你怎么评估 Agent 效果？
- eval harness 怎么搭？
- benchmark 怎么设计？
- pass@k 是什么？
- 只跑几个案例有意义吗？
- 模型升级后怎么防回退？

回答方向：

> 评估不是看模型最后说得好不好，而是看任务有没有完成、轨迹是否可信、结果是否进了真实系统状态。

接回 ApplyFlow：

- Task：固定用户画像和岗位池。
- Transcript：排序、解释、投递清单、状态回填、反馈记录。
- Outcome：岗位是否进入投递清单，状态是否回填。
- Grader：代码脚本 + LLM/人工抽检 + 用户反馈。
- 投递漏斗：投递清单候选率、状态回填率、Bad Case 率。

一句话：

> 我会按 Task / Transcript / Outcome / Grader 来评估。ApplyFlow 里最重要的不是模型说“我推荐”，而是用户是否真的把岗位推进到投递清单和状态回填。

### 4.5 数据迭代题

常见问法：

- 你有用户数据吗？
- 用户反馈怎么转成迭代？
- 指标提升从哪来？
- Bad Case 怎么治理？
- A/B 怎么做？

回答方向：

> 不假装大规模增长。当前是小样本内测和 dogfooding，就讲清样本来源、指标口径、改版前后同口径复测。

接回 ApplyFlow：

- 数据来源：本人线上 dogfooding + 朋友试用 + 固定测试画像。
- 反馈问题：点击投递链接后内容混乱。
- 迭代动作：收敛为打开投递链接、加入投递清单、标记已投递、反馈误判。
- 指标：投递清单候选率 8.8% → 16.7%，状态回填率 33.3% → 58.8%。
- 边界：这是小样本同口径复测，不是大规模线上增长。

一句话：

> 我现在不把它包装成 DAU 或商业化数据，而是讲清楚核心漏斗怎么从用户反馈里被优化。

### 4.6 工程落地题

常见问法：

- 用 AI Coding 遇到什么难点？
- 怎么保证 Codex 生成的代码不乱改？
- 怎么做回归？
- 怎么处理缓存、状态错位、线上问题？
- 怎么把不稳定的黑盒变稳定？

回答方向：

> AI Coding 不是让模型写完就结束，而是把模型放进工程流程里：上下文、边界、验证、复盘都要明确。

接回 ApplyFlow：

- AGENTS.md：规定文档读取、不可改边界、验证和 review。
- CONTEXT.md：保持当前工作现场。
- TIMELINE.md：记录每次阶段变更。
- Focused Review：检查正确性和安全边界。
- 验证脚本：production smoke、UI smoke、排序 gate、forged userId。

一句话：

> 我的项目不是只用 Codex 写代码，而是把 Codex 当成一个需要治理的 Agent，给它上下文、规则、验证和复盘。

### 4.7 知识盲区题

常见问法：

- 你会 SFT / RLHF / Agentic RL 吗？
- RAG 怎么做召回和 rerank？
- 多模态 Agent 怎么评估？
- MCP / LangGraph / AutoGen 怎么看？
- 大模型训练数据怎么构造？

回答方向：

> 不要硬装。先承认自己没有完整落地，再讲理解、项目映射和下一步。

通用模板：

> 这个方向我没有完整生产落地，所以我不会把它说成自己的项目经验。但我理解它要解决的是……在 ApplyFlow 里相近的问题是……如果后续要做，我会先从……数据/指标/边界开始，而不是直接上复杂框架。

例子：

> RAG 不是 ApplyFlow 当前核心，因为当前主线是岗位排序和投递状态。但如果未来接入公司信息、面经、政策或用户历史申请记录，我会把它设计成检索增强模块，重点评估召回覆盖、引用准确、回答是否基于证据，以及是否污染主排序。

## 5. 常见陌生题映射表

| 面试官问 | 先归类 | 接回项目的答法 |
| --- | --- | --- |
| RAG 怎么评估 | 评估 / 知识盲区 | ApplyFlow 当前不是 RAG，但公司信息和面经可扩展为 RAG；评估看召回、引用、幻觉、用户决策帮助 |
| 为什么不用 LangGraph | Agent 架构 | 先用轻量 workflow 和状态机，因为当前任务边界清楚；复杂多 Agent 等到流程复杂度超过当前系统再引入 |
| Prompt injection 怎么办 | 系统边界 | Prompt 不够，必须有 schema、权限、工具白名单、用户确认和日志 |
| Agent 为什么不是玩具 | 业务 / 评估 | 看是否有真实任务、状态推进、反馈闭环、评估脚本和失败兜底 |
| 你怎么做 benchmark | 评估 | 固定用户画像和岗位池，比较 TopN、误排、状态回填、Bad Case，不只看单条回答 |
| 用户说 AI 不可信怎么办 | 数据迭代 | 增加可解释理由、风险提示、反馈入口和人工确认；用误判反馈进入复测 |
| P95 延迟太高怎么办 | 工程落地 | 缓存、降级、异步、减少不必要 LLM 调用，确定性逻辑不走模型 |
| Token 成本太高怎么办 | 工程落地 | 结构化输入、只在语义判断用模型、复用中间结果、把规则判断下沉到代码 |
| 要不要全自动投递 | 系统边界 | 不默认全自动，高风险动作由用户确认；AI 负责建议和预填 |
| SFT 数据从哪里来 | 知识盲区 / 数据 | 来自真实 Bad Case、用户修正、投递结果和人工标注；当前阶段先做日志和分类 |
| Agentic RL 怎么看 | 知识盲区 | 需要可验证 reward 和安全边界，当前项目先做评估和 Bad Case，不急于训练 |
| 多模态怎么接 | 知识盲区 | 先看场景必要性；简历截图、岗位截图可结构化，但当前主线是文本/岗位状态 |
| AI 客服怎么设计 | 业务场景 | 套同一框架：问题分类、知识检索、工单状态、人工转接、满意度和解决率 |
| AI 内容安全怎么做 | 网易实习 | 风险分类、Prompt 样例、审核规则、Bad Case、人工复核和复测 |
| AI Coding 怎么保证质量 | 工程落地 | AGENTS.md、CONTEXT、验证脚本、Focused Review、分层验证 |

## 6. 你需要背的不是 100 道题，而是 6 句话

1. 我会先从真实任务出发，不先堆技术名词。
2. 我把 AI 能力和确定性系统分开，模型做语义判断，系统做状态、权限和门禁。
3. Prompt 是软约束，Schema、校验、日志、人工确认才是硬治理。
4. 评估要看任务结果、执行轨迹和真实系统状态，不只看模型输出。
5. 我当前没有大规模线上数据，所以用小样本同口径复测、Evidence Log 和 Bad Case 证明迭代能力。
6. 不会的技术我不会硬装，会说明理解、项目映射和下一步落地路径。

## 7. 三天高效复习法

### 第一天：只练归类

拿任意面试题，先不答内容，只判断它属于 7 类里的哪一类。

目标：

- 看到 RAG、benchmark、pass@k，就反应到“评估/知识盲区”。
- 看到 prompt injection、权限、隐私，就反应到“系统边界”。
- 看到用户数据、AB、指标，就反应到“数据迭代”。

### 第二天：只练接回项目

每道题都强制接回 ApplyFlow、网易实习或 Codex 开发流程。

目标：

- 一句话说题型。
- 一句话接项目。
- 一句话讲方法。

### 第三天：只练承认边界

重点练不会的题。

模板：

> 这个方向我没有完整生产落地，所以我不会把它说成我的项目经验。但我理解它核心解决的是……在 ApplyFlow 里相近的问题是……如果要继续做，我会从……开始验证。

这句话很重要。它比硬背一个半懂不懂的概念安全得多。

## 8. 面试控场的底层心法

你不是去和 AI 科班候选人比“谁背的名词更多”。你要让面试官看到：

- 你知道自己项目的边界。
- 你能从真实用户问题出发。
- 你能把 AI 的不稳定性变成系统问题处理。
- 你能用数据和 Bad Case 迭代。
- 你不会乱吹没做过的东西。

最稳的个人定位：

> 我不是算法研究型候选人，但我是能用 AI 工具把真实业务问题做成产品闭环的人。我更关注模型能力进入真实流程后，怎么被约束、评估、复盘和迭代。

这句话要背熟。它能把你的劣势变成一个清晰定位。

## 9. 面试时的安全边界

不要说：

- 我精通所有 AI Agent 框架。
- 我做过完整 RAG / SFT / Agentic RL 生产系统。
- 我有大规模线上用户数据。
- 我的项目已经是成熟商业 SaaS。
- 我能全自动替用户投递。

可以说：

- 我了解这些方向的核心问题，但我的项目重点在 AI 求职执行闭环。
- 我当前做的是小规模内测和线上 dogfooding，重点是迭代证据。
- 我不会把高风险执行交给模型直接做。
- 我更擅长把 AI 能力落到产品流程、评估和边界治理里。

## 10. 官方资料和现实趋势给我们的结论

我用官方资料校准后，结论和你的项目路线是对齐的：

- Anthropic 的 agent 资料强调 workflow 和 agent 要区分，很多场景应该先用简单、可组合的 workflow，再在需要动态判断的地方引入 agent。
- Anthropic 的 agent eval 资料强调 agent 会多轮调用工具、修改状态，所以评估不能只看最后回答，还要看任务轨迹、结果和人工/用户反馈。
- OpenAI 的 evals 资料强调用可复现评估来测试模型输出是否满足任务标准，并在模型或提示词变化后持续迭代。
- OpenAI 的 structured outputs 资料强调 schema adherence，比普通 JSON mode 更适合把模型输出接进应用系统。

这说明现实面试真正看重的不是你背了多少框架名，而是你能不能讲清：

> 场景是否真实，Agent 是否必要，边界是否可控，效果是否可评估，问题是否能迭代。

## 11. Focused Review 自审记录

Correctness Findings：

- 本文档将不断扩张的 AI 面试题收敛为 7 类问题路由，避免继续堆题库。
- 每一类都给出可接回 ApplyFlow、网易 AIGC 实习或 Codex 开发流程的回答锚点。
