# 00 AI 岗位面试总控与复习路线

最后更新：2026-06-02

## 1. 使用方式

这份文档是复习入口，不是题库。面试时不要急着背 ApplyFlow，也不要每道题都硬拐项目。正确顺序是：

```text
先回答概念
-> 说明主流项目会怎么做，最好能拿 Claude Code / OpenAI Agents / Anthropic Agent 方案做对比
-> 如果 ApplyFlow 做过，再讲我怎么落地
-> 如果 ApplyFlow 没做过，讲我为什么没做，以及如果接入怎么验证
```

三份主文档分工：

1. `00_先看这个：AI面试总控与复习路线.md`：答题方法、知识地图、复习路线。
2. `01_ApplyFlow项目面试主线.md`：面试官从简历和作品集深挖 ApplyFlow 时怎么答。
3. `02_深挖问答与防守口径.md`：AI Agent / AI 产品 / AI 应用岗高频知识点和防守回答。

03 文档仍作为专项补充：

- `03_ApplyFlow样本评估与Agent迭代面试话术.md`：专门复习 1000 样本评估、城市 bad case 和地点约束修复。

## 2. 答题总原则

### 原则 1：先讲人话，再讲术语

不要一上来堆框架名。比如问 Agent 评估，先说：

> 我不会只看模型有没有返回结果，而是看它的决策、动作和状态有没有符合用户目标。

然后再补充结构化输出、评估集、回归门禁、人工复核这些术语。

### 原则 2：有项目证据就讲深，没做过就讲边界

如果知识点 ApplyFlow 做过，就讲到具体指标、验证脚本、状态边界和 bad case。  
如果没做过，比如 RAG、多 Agent、模型训练，不要装成已落地。正确答法是：

> 这个方向我没有在 ApplyFlow 里生产落地，但我知道它解决什么问题。如果接入，我会先定义任务、数据来源、评估指标和失败兜底，而不是为了简历好看硬加。

### 原则 3：每个回答都要有“产品判断”

面试官喜欢的不是背八股，而是你能说清楚为什么这样取舍。比如：

- 为什么不全自动投递：因为求职提交是高风险动作，错误成本高。
- 为什么先做岗位判断而不是简历改写：因为岗位判断更容易用固定岗位池和用户行为验证。
- 为什么城市命中低还能放作品集：因为 Evidence Log 的价值是发现、归因和复测问题，不是只展示漂亮结果。

### 原则 4：重要知识点要有“顶级项目延伸”

面试官问 RAG、上下文、Memory、多 Agent、Coding Agent 时，不要停在概念层。更好的答法是：

```text
基础概念
-> 主流方案分型
-> Claude Code / OpenAI Agents 这类顶级项目怎么体现
-> 我怎么看这个取舍
-> 如果接入 ApplyFlow，怎么验证
```

例子：Memory。

> Memory 不是把所有历史聊天塞进上下文，而是决定什么值得长期保存、什么时候取、什么时候忘。主流做法大致分两类：规则式记忆，比如项目规则文件、团队规范、用户显式偏好；半规则式或混合记忆，比如先加载摘要和索引，再由 Agent 按任务去查历史记录。Claude Code 公开文档里更强调 `CLAUDE.md`、自动 memory、按需读取和 compact 后重注入项目规则，而不是把所有长期记忆都做成黑盒向量 RAG。原因是代码任务里 source-of-truth 是当前仓库，记忆只能做辅助，不能替代实时文件和测试结果。

### 原则 5：回答要像“六边形战士”

AI 岗位面试官喜欢的不是单纯懂概念，而是能同时覆盖业务、技术、数据、协作、失败复盘和下一步迭代。高压追问时尽量按这个六边形回答：

| 维度 | 回答里要出现什么 |
|---|---|
| 业务 | 用户是谁，真实痛点是什么 |
| 技术 | 用了什么方案，为什么不是只调 Prompt |
| 指标 | 上线后看什么数据，不要只说“体验变好” |
| 风险 | 幻觉、越权、延迟、成本、错误恢复怎么兜底 |
| 协作 | 算法、研发、测试、运营怎么对齐 |
| 复盘 | 如果失败或效果不通，怎么定位、调整和复测 |

例子：AI 产品最大局限。

> 我不会泛泛说伦理或隐私。更具体地说，当前 AI 产品最大局限是“不确定性难以被用户正确感知”。幻觉可以靠 RAG、结构化输出和强约束 Prompt 缓解，但系统仍然要告诉用户什么时候不确定，比如给置信度提示、二次确认入口、联网搜索或人工复核。ApplyFlow 里的城市 bad case 就是类似问题：系统知道岗位方向相关，但没有把地点不确定显式暴露给用户，所以后续我把地点约束变成输出规则和确认动作。

## 3. 五种答题模式

### 模式 A：ApplyFlow 做过的知识点

结构：

```text
概念一句话
-> 行业主流做法
-> ApplyFlow 怎么做
-> 指标或验证结果
-> 我的判断
```

例子：Agent 输出评估。

> Agent 输出不只有文本，也包括排序、优先级、下一步动作和状态变化。主流做法是先定义输出规则，再用固定评估集、轨迹日志和人工抽检验证。ApplyFlow 里我评估 Top10 排序、高优先级候选、推荐解释和下一步建议。1000 样本评估显示岗位方向可用，但城市约束没进入完整规则，所以我后续把地点从普通分数项升级为可确认、可复测的输出规则。

### 模式 B：项目没做过但必须懂的知识点

结构：

```text
承认没做
-> 说明它解决什么问题
-> 讲主流方案
-> 讲如果接入 ApplyFlow 会怎么验证
```

例子：RAG。

> ApplyFlow 当前没有落地 RAG。我理解 RAG 解决的是模型参数里没有最新、私有或可追溯知识的问题。主流做法是文档清洗、切分、召回、重排、带引用生成，再评估召回覆盖、引用准确和答案可用性。如果接入 ApplyFlow，我会优先用于公司资料、岗位政策、历史投递记录和面经，不会让 RAG 直接污染岗位排序主逻辑。

### 模式 C：被质疑“只是调规则”

结构：

```text
先承认单点看起来像规则
-> 解释真正差异在输出合同和闭环
-> 讲项目证据
```

例子：

> 如果只是把地点权重调大，那确实只是调规则。但我做的是 Agent 输出规则治理。地点不匹配不只是扣分，而是会影响是否给高优先级、是否建议推进、是否提示用户确认地点。也就是说，系统不只是给一个分数，而是知道哪里不确定，并把不确定性交给用户确认和复测。

### 模式 D：面试官问顶级项目或行业趋势

结构：

```text
先讲可验证事实
-> 抽象成方法论
-> 映射到我项目里的做法
```

可用素材：

- OpenAI Agents SDK：强调工具、编排、状态、审批、guardrails、tracing 和 eval。
- Anthropic Building Effective Agents：先用简单方案，只有当复杂系统能明显改善结果时才加复杂度。
- Claude Code 公开分析：真正的壁垒不只是模型，而是权限、上下文压缩、工具设计、子任务隔离、会话记录和验证流程这些 harness。
- OpenAI Structured Outputs：JSON mode 只保证合法 JSON，结构化输出才强调符合 schema。

### 模式 E：不会或没做过

结构：

```text
不装懂
-> 讲我对业务用途的理解
-> 讲验证方式
-> 回到我的优势
```

例子：

> 这个技术我没有生产落地过，所以我不会硬说自己做过。但我会先判断它解决的是知识召回、工具连接、状态编排、记忆管理还是评估观测问题。我的优势不是底层模型训练，而是把 AI 能力放进真实业务流程，讲清边界、指标、反馈和工程治理。

## 4. AI 岗位知识地图

| 知识点 | 面试官真正想听什么 | ApplyFlow 可用证据 |
|---|---|---|
| Agent vs workflow | 你是否知道什么时候该自治，什么时候该固定流程 | ApplyFlow 是 Agent workflow，不是模型自由行动 |
| 工具调用 | 你是否知道模型不能直接可信执行动作 | 插件只预填；服务端校验 400/401/403；高风险动作用户确认 |
| 结构化输出 | 你是否会把模型输出变成可校验规则 | Top10、高优先级候选、解释、下一步建议、地点确认 |
| Agent 评估 | 你是否能从文本评估升级到任务评估 | 1000 样本、Top1/Top10、高优先级候选、城市 bad case |
| Guardrails | 你是否知道 Prompt 不是安全边界 | Schema、权限、状态机、人工确认、Focused Review |
| Tracing / 日志 | 你是否能定位错误发生在哪一步 | CDE 排查、Evidence Log、状态回填、bad case 记录 |
| RAG | 你是否知道知识从哪里来、引用准不准 | 当前未做；未来用于公司资料、岗位政策、面经和历史投递 |
| 记忆系统 | 你是否知道记忆、上下文和 RAG 的区别 | 当前未做长期记忆；可对比 Claude Code 的 `CLAUDE.md`、auto memory 和 OpenAI progressive disclosure |
| 多 Agent | 你是否知道复杂度不是越高越好 | 当前单 Agent + workflow；未来可拆岗位、材料、投递、复盘 |
| Coding Agent | 你是否知道 AI Coding 需要 harness | AGENTS.md、CONTEXT.md、smoke、review、安全边界门禁 |
| AI 产品指标 | 你是否能定义收益指标和护栏指标 | 候选率、回填率、Top10 命中、误推荐、用户隔离、成本 |
| 上线复盘 | 你是否能复盘 A/B、失败和冷启动 | 流量分配、统计检验、bad case 归因、L1/L2/L3 分层复测 |
| Agent Harness | 你是否知道 Agent 运行底座不只是 Prompt | 工具协议、上下文记忆、编排、可观测、评估、安全治理 |
| 模型选型 | 你是否按任务选模型，而不是背排行榜 | 确定性校验不用强模型，语义判断和 bad case 归因才用模型 |

## 6. 面试红线

不要说：

- 我做了全自动求职 Agent。
- 我能自动帮用户提交投递。
- 我做了简历改写、求职信生成、RAG、多 Agent、模型训练。
- 1000 样本是正式线上 production 数据。
- 城市 bad case 已经完全修好。
- 我靠 Prompt 保证安全。

应该说：

- ApplyFlow 是求职决策与执行闭环 Agent / Agent workflow 原型。
- 高风险动作由用户确认，系统做权限、状态和日志。
- 1000 样本是 production-like 本地真实岗位池副本评估。
- 城市 bad case 已完成第一轮地点约束修复和 L2 误推治理复测，但还需要阶段性全量复测，不能直接宣称 Top10 城市命中率已提升。
- Prompt 是软约束，真正的治理来自结构化输出、Schema、权限、状态机、日志、review 和人工确认。

## 7. 90 分钟复习路线

| 时间 | 复习内容 |
|---|---|
| 10 分钟 | 背第 3 节五种答题模式 |
| 15 分钟 | 背第 4 节知识地图，每个知识点说一句人话 |
| 20 分钟 | 背 01 的 30 秒介绍、3 分钟故事和 1000 样本评估回答 |
| 20 分钟 | 背 02 的 Agent 评估、结构化输出、guardrails、Claude Code 启发 |
| 15 分钟 | 背 RAG、记忆、多 Agent、模型选型这些没做过但要会防守的题 |
| 10 分钟 | 只看红线，避免面试时说过头 |

## 8. 最重要的 5 个口播

1. ApplyFlow 是什么。
2. 为什么不是全自动海投。
3. 怎么评估 Agent 输出。
4. 城市命中低怎么归因，为什么不是简单调规则。
5. Codex / Claude Code 这类 Coding Agent 给你的启发是什么。
6. AI 产品最大局限是什么，你怎么具体突破。
7. 如果 A/B test 或模型效果失败，你怎么复盘。
