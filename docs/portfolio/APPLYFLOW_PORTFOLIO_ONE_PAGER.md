## ApplyFlow｜AI 求职执行 Agent

ApplyFlow 是一个面向求职场景的 AI 执行系统，围绕“先筛后投”重构求职流程：先帮助用户从大量岗位中判断哪些值得优先看，再通过 Shortlist、Compare、投递状态和反馈复盘，把求职从手工海投变成可追踪、可解释、可迭代的工作流。

## 用户问题

- 岗位信息太多，手工逐条判断成本高。
- 传统求职工具偏信息展示，缺少“为什么这条岗位值得投”的解释。
- AI 工具容易停留在单点生成，缺少状态管理、反馈复盘和产品边界。
- Demo 数据、测试用户和真实内测用户如果混用，会影响可信度和安全性。

## 核心方案

```text
岗位导入
→ 岗位标准化 / 去重
→ 用户偏好建模
→ 多维匹配排序
→ Shortlist / Compare
→ 投递状态管理
→ 用户反馈 / Bad Case
→ 迭代复盘
```

## 产品亮点

1. **用户偏好建模**
   将求职意图拆解为目标角色、行业方向、城市偏好、公司类型、排除项与投递可行性等维度。

2. **可解释岗位优先级**
   不只给分数，还展示推荐理由、风险点、下一步动作，帮助用户理解 AI 决策。

3. **端到端求职工作流**
   支持岗位导入、Shortlist、Compare、tracker、feedback、follow-up，避免停留在单点 LLM Demo。

4. **评测与回归验证**
   基于 5000+ 条真实岗位数据验证不同求职画像下的排序稳定性，降低低质量岗位误排和推荐漂移。

5. **Demo 到内测的产品化治理**
   区分 demo、真实岗位池和白名单用户数据，关注用户数据隔离、测试数据污染防控、Bad Case 记录与迭代优先级管理。

## 当前证据

- 真实岗位池：5000+ 条岗位用于排序验证。
- 演示岗位池：覆盖产品、数据、算法、后端、运营等岗位方向，支持稳定展示不同用户画像下的结果差异。
- 多用户边界：已完成 demo / 真实岗位池 / 白名单用户数据隔离验证。
- 安全边界：后端不信任前端传入的用户归属字段，避免用户数据串号。
- 内测计划：准备通过本人 dogfooding 与朋友试用记录 Bad Case、流程卡点和迭代反馈。
