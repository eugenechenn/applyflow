# ApplyFlow 飞书作品集结构

目标：做一个面试官 3-5 分钟能看懂的在线作品集页面。
建议标题：`ApplyFlow｜AI 求职执行 Agent 作品集`

## 1. 首页摘要

放在最顶部，不超过 200 字：

> ApplyFlow 是一个 AI 求职执行 Agent，围绕“先筛后投”重构求职流程，覆盖岗位导入、用户偏好建模、可解释排序、Shortlist/Compare、投递状态管理和反馈复盘。项目当前处于 Demo + 3-5 人白名单内测准备阶段，重点验证 AI 应用从 Demo 到真实试用之间的业务闭环、评测证据和数据边界。

按钮/链接：

- 正式 Demo 链接：`https://app.apply-flow-use.com`，`workers.dev` 不再作为正式作品集入口推荐
- 一页版 PDF：待填
- Evidence Log：已补用户反馈、投递漏斗、production-like 1000 样本评估和下一轮迭代
- GitHub / README：可选，技术面再给

## 2. 产品问题

用 3-4 个 bullet：

- 求职者面对大量岗位，缺少可解释的优先级判断。
- 普通求职工具偏信息展示，缺少状态管理和反馈复盘。
- 单点 AI 生成工具容易停留在 Demo，缺少评测与产品边界。
- 多用户内测前必须处理 demo 数据、真实岗位池和用户数据隔离。

建议直接复制：

```text
→ 多维匹配排序

→ 用户反馈 / Bad Case
→ 迭代复盘
```

## 4. 核心亮点

建议分 5 个小卡片：

1. 用户偏好建模
2. 可解释岗位优先级
3. 端到端求职工作流
4. 真实岗位池排序验证
5. Demo 到内测的数据隔离与 Bad Case 机制

## 5. 指标与证据

不要写虚假的增长数据。写真实证据：

- 真实岗位池：5000+。
- 演示岗位池：覆盖多个岗位方向。
- 投递流程复测：5 个测试画像同口径走查，投递清单候选率 8.8% -> 16.7%，状态回填率 33.3% -> 58.8%。
- production-like 1000 样本评估：1000/1000 完成，错误样本为 0，Top10 不足为 0；Top1 岗位方向命中 88.8%，Top10 岗位方向命中 92.4%。
- 高优先级候选评估：Top1 属于高优先级候选 90.0%，Top10 平均高优先级候选 8.25 个；高优先级候选方向命中强，但城市约束不足。
- 用户隔离：demo / 真实岗位池 / 白名单用户隔离。
- 试用证据：本人 dogfooding + 朋友试用仍需继续补真实截图和原话。

## 6. Bad Case 与迭代

从 Evidence Log 中挑 3 个案例：

| Bad Case | 归因 | 处理 | 复测 |
|---|---|---|---|
| 点开投递链接后不知道是否要回系统记录 | 投递主路径不清，首屏入口过多 | 收敛为投递清单主路径 | 候选率 8.8% -> 16.7%，回填率 33.3% -> 58.8% |
| Top10 城市命中率低 | 地点字段脏、城市硬/软偏好未区分、高优先级判断未吃住地点约束 | 补地点标准化、城市约束、高优先级降级和地点确认 | L2 已验证误推治理，后续阶段性跑 1000 样本 |
| 高优先级候选方向强但城市弱 | 高优先级候选池相关，但地点约束没有进入输出规则 | 将地点不确定显式暴露给用户 | 700 个误推候选直接推进率 100.0% -> 0.0% |

## 7. 当前边界

必须如实写：

- 当前不是公开 SaaS。
- 当前不是 Production Auth Ready。
- 当前不承诺全自动投递。
- 当前不承诺简历改写、求职信生成、RAG、多 Agent 或模型训练已落地。
- 当前重点是 demo、dogfooding、3-5 人白名单内测准备和 production-like 评估证据链。
